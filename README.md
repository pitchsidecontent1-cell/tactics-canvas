# Tactics Canvas

A football (soccer) tactics board web app — browse a library of formations and historic managers' title-winning XIs, then drag players and draw tactical arrows on an interactive pitch to explore ideas. Shipped as **Shape / Play**.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)

## Where things live

- `artifacts/formation-board` — the shipped product. Almost all UI and interaction logic lives in one file, `src/App.tsx` (formation/player state, drag-to-reposition, tactical-arrow drawing). Editorial copy (formation write-ups, manager/era history, fun facts) is kept separate in `src/formation-content.ts` — edit content there without touching UI code.
- `artifacts/api-server` — Express API. Currently only exposes `GET /api/healthz`; not yet wired to the product.
- `artifacts/mockup-sandbox` — Replit-internal component preview tool used during development. Not part of the shipped product.
- `lib/api-spec/openapi.yaml` — source of truth for the API contract.
- `lib/api-client-react`, `lib/api-zod` — generated from `openapi.yaml` via Orval codegen; treat `src/generated/` in each as build output, don't hand-edit.
- `lib/db/src/schema` — Drizzle schema (source of truth for the DB shape). Currently an empty scaffold — no tables defined yet.
- `attached_assets/` — pasted-in reference material, exposed to Vite artifacts via the `@assets` alias.

## Architecture decisions

- Each `artifacts/*` folder is an independently deployable Replit "artifact" (`.replit-artifact/artifact.toml` defines its run commands, port, and env) — the split isn't just by concern, it's a deploy boundary.
- API contract-first: `openapi.yaml` is the source of truth; `api-client-react` and `api-zod` are generated output, regenerated via the `codegen` script rather than edited by hand.
- `formation-board` is currently fully client-side and has no dependency on `api-server` or the database — the API/DB stack exists as scaffolding but isn't yet wired to the product.
- `lib/*` packages use TypeScript project references (`tsc --build`) for incremental, dependency-aware builds; `artifacts/*` packages typecheck independently instead.
- Shared dependency versions are pinned centrally via the pnpm `catalog:` in `pnpm-workspace.yaml`, with a 1-day minimum release age as a supply-chain guard.

## Product

- Library of formations (4-4-2, 4-3-3, 4-2-3-1, and ~20 others) with tactical write-ups: in/out-of-possession shape, key principles, two key roles, main strength, and main vulnerability.
- "Managers" library: historic eras from four title-winning managers (Ferguson, Guardiola, Mourinho, Ancelotti) with real starting XIs, era summaries, and per-player facts.
- Interactive pitch: drag player markers to reposition them, rename players inline, reset to the formation's default shape, or clear the board.
- Tactical arrows anchored to players — run (solid), pass (dashed), or off-ball movement (curved) — selectable and deletable via keyboard.
- Search/filter the formation library by name.

## Gotchas

- Vite artifacts and `api-server` read `PORT` from the environment (and `BASE_PATH` for Vite artifacts) and throw on startup if it's missing. Replit's `artifact.toml` injects these automatically; set them manually when running commands outside Replit.
- Don't hand-edit `lib/api-client-react/src/generated` or `lib/api-zod/src/generated` — they're regenerated by `pnpm --filter @workspace/api-spec run codegen`. Change `openapi.yaml` instead.
- Don't rename `info.title` in `openapi.yaml` — generated import paths depend on it.
- Must use pnpm — the root `preinstall` script blocks npm/yarn installs.
